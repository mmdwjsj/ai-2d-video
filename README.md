# 泰国本地生活 AI 双语短视频系统

项目代号 `thai-daily-life-ai-video`。Windows 本地运行的模块化单体工作台：人物六视图资源库（默认 3 人、可按剧本自由增删）+ 泰国生活场景库，从主题生成中/泰双语剧本与分镜，逐镜头编辑，最后合成竖屏短视频。

## 当前交付范围

**基础工作台 + 真实 MP4 导出**都已可运行：从主题到可播放成片，全程本地、不需要任何 AI 密钥。

- 已可用：项目语言类型（决定剧本框与成片版本）、3 个菜单（项目库 / 制作 / 出片）、剧本规范与一键示例、项目管理、人物增删与六视图资源库一键带入、12 场景库、**场景匹配审阅（自动匹配依据可预览、可逐镜头手动改且不被重新分镜覆盖）**、中/泰剧本编辑、规则式自动分镜、单镜头编辑/排序/锁定/版本恢复、持久化任务队列、自动保存、项目 JSON 导出、**本地 MP4 合成**（场景插画 + 人物参考图 + 中/泰字幕 + 镜头动效 + 音轨）、成片列表播放/下载。
- 成片规格：1080×1920 / 30fps / H.264 + AAC，含片头片尾；每个镜头时长按配音实测值撑开，视频不会早于配音结束。
- 中文/泰语配音已接通 `edge-tts`（联网、无需密钥），逐句合成并自动缓存；合成好的整镜头配音还会留在 `assets/audio/tts/shot-<镜头>-<语种>.wav`，预览可直接试听，下次 TTS 联网失败也能兜底，不会整片没声。单句失败会重试一次，仍失败则回退镜头已挂 WAV，并在导出结果里给出失败原因（不再静默标成「未配置 TTS」）。图像 / 视频 Provider 仍默认未配置，绝不产假素材，单镜头重生成会明确提示「仅重置」，整片导出不受影响。
- 接入点见 `docs/ARCHITECTURE.md` 与 `docs/VIDEO_RENDER.md`。第一版明确不做 LoRA 训练、3D 建模、多人协作、云端素材、自动发布、专业非线编。

## 五分钟示例（不知道怎么开始，就先跑这个）

```bash
npm install
npm run example
```

一条命令走完整条链路：**新建项目 → 输入主题 → 生成中/泰双语剧本 → 自动分镜 → 单独编辑镜头/换场景 → 锁定保护 → 单镜头重生成 → 导出项目 JSON**，每一步的真实结果都会打印出来。脚本会复用已在 4173 运行的服务；如果服务没起，它自己在 4188 临时起一个、结束精确停掉，**不会动你手动启动的服务**。

示例项目叫「示例：下班后去夜市吃冬阴功」，**会保留在工作台里**，打开界面就能直接点开看。重复运行只做只读展示，不覆盖你改过的内容；`npm run example -- --fresh` 才重建并重跑完整流程。

### 界面照着点

先 `npm run build && npm start`，浏览器打开 `http://localhost:4173`。**侧栏只有 3 个菜单**，页面顶部有「第 N / 3 步」引导卡片，写清这一步该做什么、下一步点哪里；侧栏左下角有「完整使用帮助」。侧栏标题栏右侧的「‹‹ / ››」可以折叠成只剩三个图标。

1. **项目库**：填项目名 → 选「语言类型」→ 新建；或直接点「打开示例项目，直接照着看」。建完直接进「制作」。
2. **制作**：一页四段，从上往下填，改完自动保存（段头显示「已保存 14:32」）：
   - 第 1 段 人物：人数按剧本定，「＋新增人物」「删除」随时可改；「从资源库选人」点一张全身照就自动带出六视图；确认名字、核心外貌与声音。
   - 第 2 段 场景：12 个泰国场景以缩略图墙展示（缩略图就是成片里的画面），点卡片可改名称/类型/地点/匹配关键词；关键词决定台词自动落到哪个场景，改完到第 4 段「场景匹配审阅」看效果。时间、天气、光线不再单独配，由场景自带（夜市=夜、办公室=白天）。可整段跳过。
   - 第 3 段 剧本：看「剧本规范」→ 粘贴规范剧本 → 生成 → 逐行校对 说话人 / 台词 / 情绪 / 动作。**当前文本引擎是本地规则模板（离线、无需密钥，未接在线 AI）**：主题只用来给内置口语句式排序、写标题与开场白、台词没命中关键词时兜底选场景，不会创作剧情；粘贴文案时另一语种栏仍是模板句，不做翻译。
   - 第 4 段 分镜：点顶部「提交并自动分镜」后自动展开；段顶「场景匹配审阅」先给出每个镜头自动配的场景缩略图与命中依据，觉得不对就点「手动选择场景」（选完 9:16 预览立刻变，且重新自动分镜不会被覆盖）。左侧点镜头、右侧改人物/动作/台词/时长，版本历史、锁定、单镜头重生成也在这段里。
3. **出片**：一页三段，从上往下看：
   - ① 成片预览：与成片同一个画面渲染器、同一条口型时间轴，9:16 逐帧播放、可暂停拖进度，还能试听该镜头的配音（**不是成片 MP4**：预览时长按镜头设定秒数，成片会按配音实测撑开）。分镜页的 9:16 小窗用的是同一套画面，也能动嘴。
   - ② 导出 MP4：确认语言类型 → 点「导出 MP4」→ 等进度 100% → 点「播放成片」验收；成片同时在 `output/<项目ID>/`，可下载。
   - ③ 任务记录：默认折叠，展开才轮询；查看任务状态、失败原因，可重试 / 取消。

想一步看到成品：在出片页点一次按钮即可，或跑 `npm run example -- --render`（示例脚本会额外渲染一份成片并打印路径）。

### 场景匹配与人工校正

自动匹配是按关键词猜的，不假装百分百准。`packages/core/src/sceneMatch.ts` 用「用户填的关键词 + 场景名切词」给每句台词打分，长词权重高于「吃 / 家」这类单字泛词；剧本行里自己写的场景提示权重最高；台词没线索才退到整篇主题，一个词都没命中就轮换到通用场景，并明确标为「程序兜底」。这个纯函数同时供服务端自动分镜和前端审阅面板使用，界面显示的建议就是真正会写入的结果。

第 4 段顶部的「场景匹配审阅」把每个镜头的自动建议缩略图、命中词、依据（剧本标注 / 台词命中 / 仅按主题 / 程序兜底）与把握程度摊开，可「只看待确认」快速定位问题镜头，点「手动选择场景」逐镜头改。改过的镜头记 `sceneSource: 'manual'`，镜头列表与预览页都会标「手动」；之后再点「提交并自动分镜」也不会被覆盖（`inheritManualSceneSelections` 按台词 / 序号把手动场景继承到新镜头）。「恢复自动」退回建议，「重新自动匹配」只重算自动镜头，「清除手动指定」才把全部推倒重来。改了场景关键词后，点「重新自动匹配」就能看到新的判定结果。

### 人物六视图资源库

每个人物的参考图固定 6 个槽位：**正面 / 侧面 / 背面 / 全身 / 半身 / 脸部**。图片有两种来源，别搞反：

- **从资源库选**：点「从资源库选人」→ 弹窗里点一张全身照，另外 5 张自动带出，同时带入该人物的姓名、核心外貌与音色设定；已有人物点「从资源库换一套」则只换这 6 张图，手改过的设定不变。
- **自己上传**：只有手动「＋新增人物」才需要逐张上传 6 张；之后想换某一张，直接点那一格上传即可。上传的图按人物 + 槽位自动追加版本，旧文件保留。

**这些图会真正用于出片**：`全身`（缺则 `正面`）那张会贴进成片画面、预览页和分镜页的镜头里，所以换人/换图在画面上立刻看得见。服务端用 `frameData.ts` 统一算出图片地址与 `calibration.json` 的嘴部标定坐标：导出截图时把图读成内联 data URI（`file://` 打开 HTML 时外链加载不到），界面预览走同源 `/assets/...` URL（不塞几 MB base64），两边嘴部坐标完全一致；文件不存在才回退到程序化 SVG 小人。新增人物只要有图就用自己的形象，不再按 id 哈希回退成旧人的样子。

资源库本体在 `assets/characters/library/`：

```
assets/characters/library/
  index.json                 资源库清单：人物 + 六张图的相对路径 + 默认设定模板
  nina/{front,side,back,fullBody,halfBody,face}.png
  aton/{...}.png
  dundun/{...}.png
```

`GET /api/character-library` 读这份清单并校验文件存在性后给前端。要加新人物：把六张图放进 `library/<slug>/`，在 `index.json` 里追加一项（可照抄现有结构），页面点「刷新资源库」即可选到，**不需要改代码**。资产由 `python scripts/build_character_library.py prepare / finalize / status` 生成与校验：正面/全身取自定稿立绘，半身/脸部按实测构图裁切，侧面/背面由图生图补齐后统一尺寸并去水印。`config/characters.json` 是新建项目默认带的三人与他们已填好的六视图。

## 语言类型（决定剧本框、配音与成片版本）

新建项目时选，页面顶部可随时切换。它是**全项目唯一真值**，落在 `projects.export_mode`：

- **中文**：只出现中文剧本框，台词 / 字幕 / 配音只做中文，成片只出中文版 MP4。
- **泰语**：只出现泰语剧本框，其它同理，只出泰语版 MP4。
- **双语（中＋泰）**：中泰双栏都在，导出双语版（泰语对白＋中文旁白/字幕）。

切换只改变显示与导出目标，**不会删除另一种语言已写的内容**；剧本页会提示「还存着另一种语言，切到双语可查看」。生成剧本时服务端按该类型只产出对应语种台词，另一侧留空。

## 剧本规范

「制作 · 剧本」段内置规范卡片与「填入规范示例」按钮，完整说明见 `docs/SCRIPT_GUIDE.md`。核心：

- 一行一句，三种行：`【场景】场景名 · 时间 · 光线`、`旁白：一句话`、`人物名＋表情动作＋说：“台词”`。
- 标准对白示例：`妮娜微笑地说：“你好，需要吃点什么吗？”` —— 生成后拆成**说话人 / 中文对白 / 情绪 / 动作**四列，台词列只留引号里的纯台词。
- `【场景】` 行只提取场景名、不生成对白行也不占镜头；`旁白：…` 是**交代当时情况和人物心情的情境说明**，不是人物台词：不进说话人下拉、不设情绪动作，成片里作为画外音字幕（不署名说话人）。
- 情绪与动作从「认真地说」「皱眉说」「慌张地说」等描述自动匹配；对白行里每行都能**下拉选常用词、也能直接打字自定义**。渲染层按情绪画不同眉眼/嘴型（笑、皱眉、慌张、冷笑、认真等），选了画面会变。
- 改对白行会同步写回中文剧本正文对应行；反过来改了正文，点「重新解析正文」更新对白行。泰语正文保持独立编辑。
- 一句 ≤ 25 字，人物名要和「制作 · 人物」段一致，泰语要日常口语而非逐字翻译。
- 结构：开头吸引点 → 2～4 轮对话 → 一句生活感受收尾。

## 视频导出（要看成品，看这一节）

**「出片」→ 点「导出 XX MP4」→ 等进度 100% → 点「播放成片」**。渲染在后台任务队列里执行，通常半分钟到一分钟，可以切到别的页面；任务记录落在 SQLite，程序关掉重启也不丢。

成片文件在项目根目录的 **`output/<项目ID>/`**，绝对路径在出片页显示，MP4 可直接在浏览器里播放 / 下载。语言类型决定主按钮导出哪个版本；出片页「③ 需要别的语言版本」可额外生成另两种版本，三份文件互不覆盖。

**本地渲染链路**：台词 → 2D 插画帧（场景配色 + 人物参考图，没图才用程序化立绘 + 双语字幕）→ 系统 Edge/Chrome 无头截图 → FFmpeg 加缓慢推近动效、拼接镜头、混音 → H.264/AAC MP4。字幕用浏览器排版，中泰文都不会出现元音错位。

**对白镜头会动嘴**：服务端按配音 WAV 的 RMS 能量包络把每个视频帧映射到闭嘴 / 小张 / 张开 / 大张四档口型（无配音时按台词长度给出开合节奏，音轨仍如实标注未配音），只截实际用到的几张口型底图，再硬链接铺成逐帧序列交给 FFmpeg，磁盘上不产生上百份重复 PNG。嘴部位置 / 宽高 / 肤色都取 `assets/characters/calibration.json` 的实测值，口型 SVG 与人物图共用 `preserveAspectRatio`/`object-fit` 映射，换人换图都不会贴歪。四档统一先用实测肤色盖掉原图那条静态嘴、再画新嘴：补丁与人物图同组 `multiply`，脸上不留亮斑；这样连吨吨那种「原图本来就是 116×59 张开的黑色口腔」也能真正闭嘴，小口型不会露出原嘴黑边。片头、片尾、无出场人物的旁白镜头仍用单张静帧。

**预览与成片同源**：预览页和分镜页不再自己画背景 / 人物贴图 / 字幕，而是请求 `GET /api/projects/:id/preview-frames`，由服务端用同一个 `shotFrameInput` + `buildFrame` 生成四档口型 HTML，并用同一条 `mouthTimeline` 给出逐帧序列；前端 `FramePlayer` 把这几档 iframe 常驻叠放，按时间轴切可见档，不重新加载、不闪。接口同时返回该镜头的配音地址，预览页可直接试听，播放时口型由音频时钟驱动，与声音对齐（浏览器拦截自动播放时点「重开声音」）；没有配音时口型按台词节奏（界面如实标注来源），无出场人物的旁白镜头仍是静帧。预览与成片唯一的差别是时长口径和推近动效，画面与声音都不再有两套实现。

**动画样片（独立验证链路，不改动主渲染）**：`npm run demo` 或 `python scripts/demo_animation.py`，产出 `output/demo/样片-三角色动画与场景切换.mp4`，静帧在 `output/demo/stills/`。它用三张定稿立绘的透明底资产（`assets/characters/cutout/`）逐帧合成 30fps 动画：嘴型由配音音频能量包络驱动、人物走路与上下起伏、厨房 → 客厅（横向推移）→ 卫生间（淡入）切换。这条链路验证的是「动作层」；主导出链路现已接入同一套配音能量驱动的口型（见上文），但走路、场景推移等动作层仍只在样片链路里，尚未合并。

**换文案出片（命令行）**：把逐句文案写成 JSON，交给同一个脚本即可，不用改代码：

```bash
python scripts/demo_animation.py --story my-story.json --out output/demo/我的短片.mp4 --title "片头标题"
```

```json
[
  {"scene": "厨房", "char": "nina",   "action": "talk", "text": "吨吨，洗手吃饭啦！"},
  {"char": "aton",   "action": "walk", "text": "周末商场人真多，先去超市买点菜。"},
  {"char": "dundun", "action": "talk", "text": "我洗好啦！"}
]
```

`scene` 可写 `kitchen/living/bath/bedroom/mall/street/car`，也可写「厨房/客厅/卫生间/卧室/商场/大街/车内」，中英别名都认；**不写 scene 时会按台词关键词自动选场景**（如「闹钟/被子」→卧室，「商场/超市」→商场，「马路/外面」→大街，「开车/堵车」→车内），实在认不出才退到客厅，日志会打印每句的判定结果。

场景不够用有两种加法：①把一张图丢进 `assets/backgrounds/`，文件名就是场景名（如 `卧室.png`、`商场.jpg`），脚本会自动注册并优先于内置场景，任意比例都会等比铺满 1080×1920；②在 `scripts/demo_animation.py` 里照 `_bg_*` 的写法加一个函数（同一套粗描线 + 平涂，颜色取自 `INK`）。

`char` 只认 `nina/aton/dundun`，音色按角色默认值取，也可用 `voice` 覆盖。字幕按像素宽度自动断行、超长句自动缩字号（最多 3 行，且避免末行只剩一两个字），配音按文本哈希缓存，换文案不会误用旧音频。

**配音：默认已接通 edge-tts**

`config/providers.json` 的 `tts.active = "command"`；三人音色写在 `config/characters.json` 的 `voices` 里：妮娜 `zh-CN-XiaoxiaoNeural`、阿顿 `zh-CN-YunxiNeural`、吨吨 `zh-CN-YunxiaNeural`，泰语用 `th-TH-PremwadeeNeural` / `th-TH-NiwatNeural`。

**为什么会联网**：edge-tts 调用的是微软在线语音服务，本机没有声学模型，所以要逐句把台词发到公网取回音频。这是本项目唯一联网点；剧本、场景匹配、画面、字幕、口型和 MP4 合成全在本机完成。按台词哈希缓存到 `assets/audio/tts/`，命中缓存不会重复联网。想完全离线就把 `tts.active` 改回 `unconfigured`（成片为字幕 + 本地氛围音），或换成本地离线语音引擎。

**本机还要装一次包**：`python -m pip install edge-tts`。一台机器常有多个 Python，装了包的未必是 PATH 里第一个；导出前会自检并挑能 `import edge_tts` 的解释器，也可设环境变量 `THAI_VIDEO_TTS_PYTHON` 或把 `tts.command` 写成绝对路径。看到 `No module named edge_tts` 是本机缺包，不是断网，导出页会给针对性的修复命令。详见 `docs/VIDEO_RENDER.md` 第 4 节。

| 情况 | 成片音轨 |
| --- | --- |
| TTS 正常（默认） | 逐句合成人声混入，镜头时长按 ffprobe 实测值撑开 |
| 本机缺包 / 命令写错 | 不逐句重试，直接给出安装或改解释器路径的建议；该镜头退回字幕并告警 |
| 联网失败 | 单句重试一次；仍失败退回字幕并告警，绝不伪造人声 |

换任意语音引擎只需改 `tts.command` / `tts.args` 模板（支持 `{text}` `{voice}` `{output}` `{language}`）；也可把 WAV 路径填进镜头的中文/泰语音频字段。详见 `docs/VIDEO_RENDER.md`。

几个容易困惑的点：

- 改中文或泰语一栏，另一栏**不会自动跟着变**，必须你确认才覆盖。
- 单镜头「重新生成画面 / 配音」在 Provider 未配置时只重置、明确提示，**不会生成假图假音频**；但整片导出不受影响，本地画面照常出片。
- 本地规则按关键词匹配场景，命中不了时会在「场景匹配审阅」里标成「程序兜底」；逐镜头手动换一次即可，之后重新自动分镜也会保留（示例已演示换两个）。
- 泰语是日常口语句式模板，不是逐字翻译，正式生成前请人工校对。
- 示例项目是**泰语**类型；切成「中文」时泰语剧本框会隐藏，内容并没有丢。

## 运行

要求 Node.js >= 22.5（内置 `node:sqlite`，免编译原生模块）、**FFmpeg + ffprobe 在 PATH**、系统装有 Microsoft Edge 或 Chrome（导出 MP4 时用来渲染画面；也可设 `THAI_VIDEO_BROWSER` 指向浏览器 exe）。`GET /api/config` 的 `capabilities.renderer` 会告诉你本机缺什么。

```bash
npm install
npm run dev:server     # 终端 A：API + 静态托管，http://localhost:4173（必须启动）
npm run dev:web        # 终端 B：Vite 开发页，http://localhost:5173
```

开发页把 `/api`、`/output`、`/assets` 一起代理到 4173。**只开 5173、不开 4173 时页面能显示但所有数据、播放、下载都会失败**（早期版本 `/output` 未代理，甚至会把 `index.html` 当成 MP4 下载下来，现已修复）。

单端口运行（前端已构建，推荐）：

```bash
npm run build && npm start   # http://localhost:4173
```

可用环境变量：`PORT`（默认 4173）、`THAI_VIDEO_ROOT`（数据根目录，默认项目根）、`THAI_VIDEO_API`（开发页代理目标，默认 `http://localhost:4173`）。

成片与项目 JSON 的下载都走 `/api` 专用接口，强制 `attachment` 并校验响应类型；拿不到真实文件时会给出明确报错，而不是保存一个 HTML 文件。详见 `docs/VIDEO_RENDER.md` 的「播放与下载」一节。

检查与测试：

```bash
npm run typecheck
npm test
```

## 数据存储

- `data/workbench.sqlite`：项目元数据、素材元数据、任务队列（**持久化**，重启不丢）。
- `data/projects/<id>/script.json`：中/泰双语剧本。
- `data/projects/<id>/shots.json`：分镜（核心数据对象）。
- `data/projects/<id>/history/shots/<shotId>/vN.json`：单镜头历史版本。
- 素材本体在 `assets/`，数据库只存相对路径与来源信息。

## 完整验收路径（到出片）

1. 项目库新建项目 → 选语言类型 → 默认带入 3 个人物与 12 个场景（人物可增删、可从资源库换人），直接进「制作」。
2. 制作 · 第 3 段输入主题（例：「下班后去夜市吃冬阴功」）→ 生成剧本（本地规则，非在线模型）→ 人工修改台词（另一侧不会被静默覆盖）。
3. 点顶部「提交并自动分镜」→ 按对白行逐行切镜，说话人、情绪、动作、场景都取对白行的值并估算时长；情境/旁白行生成无出场人物的画外音镜头，字幕不署名说话人。
4. 制作 · 第 4 段先看「场景匹配审阅」核对自动配的场景（命中词 / 依据 / 把握程度），不对的手动换；再逐镜头改动作/表情/人物/台词、排序、锁定、看版本历史并恢复。之后重新自动分镜不会冲掉手动指定的场景。
5. 出片页点「导出 MP4」→ 进度到 100% → 播放成片核对字幕、画面、时长与音轨。
6. 出片页展开「任务记录」查看每个任务的状态与失败原因；「下载项目 JSON」做纯数据备份。

**长页面怎么不迷路**：制作页 / 出片页都是一页多段，往下滚时当前段的标题会吸顶，贴在顶部项目条下方（段头层级低于项目条，不会遮住提交按钮）；滚出这一段时由下一段段头自动接力。段头带「正在看」标记，`收起 / 立即保存` 滚到哪儿都能点；顶部段导航同步高亮当前段，点一下跳段并在平滑滚动期间锁定高亮。吸顶高度按实际测量写入 CSS 变量，窄屏换行、锚点跳转、键盘聚焦输入框都会自动让开这两层。

## 约定

- 镜头状态与版本以 `shotId` 为单位，**重新生成任一镜头不影响其他镜头**；批量操作跳过已锁定镜头。
- 修改中文或泰语台词时只提示差异，**必须人工确认才能覆盖另一侧**。
- 视频总时长按最终音频时间轴计算，不允许视频早于配音结束（`video-renderer/timeline.ts` 的 `computeTimeline` 已落实，ffprobe 实测值为准）。
- AI 模型、生成参数、素材来源、成本记录在任务与素材元数据里，可追溯。
